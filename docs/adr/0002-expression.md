# ADR-0002: 式指向構文 (2026-10-10 -)

## 決定

- 式指向構文を採用する。

理由: mutable reference などを扱いはじめると自然と ownership が重要になる。その場合、式指向のほうがはるかに扱いやすい。そもそも一般論として、関数型プログラミングの良い部分を手続き型言語に取り込むなら式指向のほうが望ましい。

## 検討した選択肢1: 文指向構文

文指向では副作用と値を分離するインセンティブが高くなる。副作用と値は不可分な部分も多い一方、必要がないときはなるべく分離するほうが見通しがよくなるため、文指向のほうがこの点ではよりよいコードを生む場合がある。

具象構文の性格によっては文指向のほうが見通しがよくなる。たとえば offside rule の扱いは Python のほうが Haskell より見通しがよい。

C family は古典的には文指向であるためこれらの言語の慣習を持ち込める利点もある。例外は Rust。

ただ、いずれも式指向構文を採用するメリットには届かない。
